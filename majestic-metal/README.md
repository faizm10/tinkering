# RepoPulse

GitHub-centered product analytics for applications that live in multiple repositories. GitHub controls repository access and organization; RepoPulse records the people, sessions, page views, and custom events generated by each product.

The app runs with deterministic demo data when external services are not configured. Production mode uses Clerk, a read-only GitHub App, Neon Postgres, and Upstash Redis.

## Included

- Next.js 16 App Router dashboard with portfolio and repository views
- Product-user profiles and chronological event timelines
- Browser SDK with anonymous identity, 30-minute sessions, consent, identify, reset, batching, and automatic page views
- HTTP batch ingestion API with schema validation, origin restrictions, idempotency, duplicate handling, payload limits, and Upstash rate limiting
- Clerk GitHub sign-in and GitHub App installation synchronization
- Drizzle schema and migration for monthly-partitioned events
- Daily aggregation and 90-day raw-event retention cron
- Tracking-key creation, rotation, and revocation
- Allowed-origin updates and complete repository-data deletion
- Per-repository Google Analytics 4 imports through the Google Analytics Data API

## Local development

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Without `.env.local`, the dashboard and ingestion endpoint run in demo mode. The demo ingestion keys are:

```text
rp_pub_demo_project
rp_sec_demo_project
```

Copy `.env.example` to `.env.local` only when you are ready to connect real infrastructure. Never commit `.env.local`.

## Production setup order

1. Link this directory to a Vercel project:

   ```bash
   vercel link
   ```

2. Provision Clerk, Neon, and Upstash through the Vercel Marketplace.
3. Pull the provisioned variables:

   ```bash
   vercel env pull .env.local --yes
   ```

4. Add the remaining secrets from `.env.example`, including `CRON_SECRET` and `DATA_HASH_SECRET`.
5. Apply the database migration:

   ```bash
   npm run db:push
   ```

6. Create and configure the GitHub App described below.
7. Deploy with Vercel.

The current workspace is intentionally not linked or provisioned automatically because selecting a Vercel project and creating billable integrations requires an explicit deployment decision.

## GitHub App configuration

Create a GitHub App owned by your user or organization with:

- Homepage URL: your deployed RepoPulse URL
- Setup URL: `https://YOUR_DOMAIN/api/github/callback`
- Webhook URL: `https://YOUR_DOMAIN/api/github/webhook`
- Webhook secret: the same value as `GITHUB_WEBHOOK_SECRET`
- Repository permission: Metadata — Read-only
- Subscribe to: Installation and Installation repositories
- Installation scope: Any account, with users choosing selected repositories

Set `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, and the PEM private key in `GITHUB_APP_PRIVATE_KEY`. Newlines may be stored as literal `\n`.

## Browser SDK

```html
<script src="https://YOUR_DOMAIN/analytics.js"></script>
<script>
  RepoPulse.init({
    projectKey: "rp_pub_...",
    endpoint: "https://YOUR_DOMAIN/api/ingest",
    consent: true
  })

  RepoPulse.identify("opaque-product-user-id", { plan: "pro" })
  RepoPulse.track("project_created", { template: "nextjs" })
</script>
```

Call `RepoPulse.reset()` on logout. If consent is initially unavailable, initialize with `consent: false` and call `RepoPulse.setConsent(true)` after permission is granted.

## HTTP ingestion

`POST /api/ingest` accepts up to 50 events and 256 KB per request. Server integrations should send the secret key as a bearer token.

```bash
curl http://localhost:3000/api/ingest \
  -H 'content-type: application/json' \
  -H 'authorization: Bearer rp_sec_demo_project' \
  -H "idempotency-key: $(uuidgen)" \
  --data '{
    "events": [{
      "id": "event-12345678",
      "name": "invoice_paid",
      "anonymousId": "server-user-123",
      "sessionId": "server-session-123",
      "timestamp": "2026-06-19T12:00:00.000Z",
      "userId": "opaque-product-user-id",
      "properties": { "amount": 4900, "currency": "USD" }
    }]
  }'
```

Product identifiers are hashed before lookup. IP addresses are never persisted. User traits are optional and should not contain sensitive personal data.

## Connect Google Analytics

Each repository can connect one GA4 property. When connected, GA4 supplies the repository overview totals, trends, top events, and acquisition sources. RepoPulse's native SDK remains optional and is still required for individual product-user timelines because the Google Analytics Data API returns aggregated reporting data.

1. In Google Cloud, enable the **Google Analytics Data API**.
2. Create a service account and download its JSON key.
3. In Google Analytics, open **Admin → Property access management**.
4. Add the service account's `client_email` as a **Viewer**.
5. In RepoPulse, open the repository's **Settings → Google Analytics** section.
6. Enter the numeric GA4 property ID and paste the service-account JSON.

RepoPulse validates the credential before saving it, encrypts it with `ANALYTICS_ENCRYPTION_KEY`, imports the latest 30 days, and refreshes the latest three days during the daily cron.

Generate a suitable encryption key without printing it:

```bash
openssl rand -base64 32 | vercel env add ANALYTICS_ENCRYPTION_KEY production
```
